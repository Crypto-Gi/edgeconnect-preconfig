# 1.4.0: local web GUI, and every captured field accounted for

The Latest release, after [1.3.2](https://github.com/Crypto-Gi/edgeconnect-preconfig/releases/tag/v1.3.2). It is the code of [1.4.0-rc.5](1.4.0-rc.5.md) with the version set, now on `main`. The pre-releases on the way were [rc.1](1.4.0-rc.1.md), [rc.2](1.4.0-rc.2.md) and rc.5 (rc.3 and rc.4 were not published; their changes are in [rc.3](1.4.0-rc.3.md) and [rc.4](1.4.0-rc.4.md)).

## What's new since 1.3.2
- **Local web GUI**: `edgeconnect-preconfig gui`. It builds a template from an appliance, alone or compared with other sites, and makes, validates and uploads the preconfigs. It also shows the appliances and preconfigs on an Orchestrator. It runs the command line's own code, and uploads are off until `<nick>_gui_preconfig_uploads=on`. See [GUI.md](../GUI.md). No branch switch is needed any more: `setup.sh` installs `main`.
- **Every captured field is accounted for.** A new source-coverage check shows that every field of 139 stored captures, over 3 target releases, is either written or named in the ledger. Settings that were dropped are now written, among them:
  - a non-Default segment's route flags and passthrough tunnel segment;
  - an IP SLA http monitor's force-DNS setting;
  - a combo port in SFP mode.
- **Values are checked before they are written.** A value of the wrong type for the target release is left out with a Gaps line. Values that `/validate` rejects are named offline, and the ledger never says "mapped" for a value the YAML does not hold.
- **Secrets:**
  - the VRRP key is redacted at capture;
  - a key under a list is a secret column;
  - no ledger line quotes a raw entry or a conversion error's value.
- **Template groups:** a field a selected template sets (routes, BGP, VRRP, OSPF) is left out, with a template-group line. BFD timers are the exception and stay written, because `/validate` needs them.
- **Orchestrator 10.0:** the converter fixes for 10.0's `/validate`.
- **Failed reads:** a read that failed during capture always gets a not-readable ledger line, never an empty value.

Full entries: [CHANGELOG.md](../../CHANGELOG.md).

## Checked
- Unit and golden tests, run in CI on Linux and macOS (Python 3.9 and 3.13) and on Windows through WSL, plus the GUI browser test in Chromium, Firefox and WebKit.
- A release gate on each fix: 139 stored captures × 3 targets, with no crash, silent drop or secret leak, and YAML byte-identical apart from the intended changes. `/validate` on Orchestrator 9.7.1 accepted every changed build.
- A full-coverage lab on five appliances (ECOS 9.6.2.1 and 9.7.1): settings configured live, captured, converted and applied back. Clean-box re-tests confirmed the ECOS 9.6.2.1 limits in `references/known-constraints.yaml`.
- An offline fuzz of 7,500 malformed captures: the leaks and silent drops it found are fixed, and nothing new failed on the re-run.

## Not checked
- A real Windows install (only WSL in CI), and Firefox and WebKit beyond the GUI smoke and accessibility test.
- `/validate` on a 9.6.x Orchestrator for the 10 paths written for 9.6.x targets, and on 10.0 for the rc.3 to rc.5 changes. Both were checked offline.
- A tunnel segment applied live (it is validated on 9.7.1).
- Shapes the Orchestrator does not send, which are on the 1.4.1 list: a truncated capture file, an error object stored as a read's data, and a list in a one-value field.
