# 1.5.0: the skill holds instructions only; the code stays in toolkit/

The Latest release, after [1.4.0](1.4.0.md). The converter's code is unchanged; this release changes how the agent skill and `setup.sh` are packaged.

## What changes
- **The skill holds `SKILL.md` only** ([decision 0021](../decisions/0021-the-skill-holds-instructions-only.md)). It no longer ships a copy of `toolkit/`, and there are no `.zip` or `.skill` release assets any more. The skill runs the `edgeconnect-preconfig` command and reads `<install folder>/edgeconnect-preconfig/toolkit/references/`, so it needs the toolkit that `setup.sh` installs (or a clone with `requirements.txt` installed and the command on the PATH). A skill uploaded on its own, such as to Claude Desktop, no longer runs.
- **`setup.sh` re-run puts every clone on `main`**, the same file in all three repositories. A clean clone on another branch, such as `gui`, is switched to `main` (the branch is kept) and pulled fast-forward. A clone with uncommitted changes, or detached on a commit `main` does not have, is left alone with a message; a diverged `main` stops the run and is not reset.
- **README**: the GUI demo and the terminal demo are at the top.

## Update
Run `setup.sh` again in the install folder. It moves every clean clone to `main` and reinstalls the skill, which replaces the old skill folder (its `scripts/` and `references/` copy is removed).

## Checked
- No file under `toolkit/` changed apart from `VERSION`: sha256 of every other file is identical to 1.4.0's, and a build with this toolkit and with 1.4.0's writes the same files apart from the version stamp and timestamps.
- Full offline suite: 731 tests pass.
- Reinstalling the skill over a 1.4.0 install leaves only `SKILL.md`.

## Not checked
- A full re-run of `setup.sh` on a fresh machine; the update step and the skill reinstall were tested on their own.
- Agents other than Claude Code reading the skill from `<install folder>/edgeconnect-preconfig/toolkit/references/`.
