# 1.4.0-rc.3: full-coverage lab fixes (pre-release)

A pre-release from the `gui` branch, after [1.4.0-rc.2](1.4.0-rc.2.md). `main` and its Latest release (1.3.2) are unchanged. The local web GUI is as in rc.2. This release changes what the converter writes and records, after a lab run that set every testable preconfig setting on five virtual appliances and converted them back.

## What changed since 1.4.0-rc.2
- **Security: the VRRP key is redacted.** `/vrrp` returns the key as `auth`, which no secret rule matched, so captures held it in clear. It is now redacted at capture. The converter writes a `<SECRET:>` placeholder, even from an older capture, and the key becomes a secret CSV column. It never reached the YAML or the CSVs before, because VRRP groups with a key were left out. Captures taken before this release may still hold VRRP keys in clear: treat them as secret.
- **Settings proven on the lab are written.** These were applied live and accepted by `/validate` on 9.7.1, and are now on the `verified` list:
  - virtual tunnel interfaces;
  - custom appliance tags;
  - secure web services;
  - NAC (on 9.7.1 and 10.0 targets, when every apply policy is trusted or labelled);
  - DHCP failover, ranges, options and NetBIOS servers;
  - IP SLA tunnel actions;
  - PPPoE DNS servers;
  - VRRP authentication.
- **The ledger never says "mapped" for a value the YAML does not hold.** Such a value is a gap named at the top of `summary.md`, and a new check, `11 ledger matches the YAML`, enforces it. This fixes a silent drop of multicast on 9.6.4 targets (56 of the gate's builds).
- **Values `/validate` rejects are named offline** and the row is refused, never changed:
  - an OSPF area type other than 0 or 1;
  - DHCP option 82 with no sub-option;
  - two dual-stack WAN entries under one label;
  - a VRRP key over 8 characters.
- **Smaller fixes:**
  - networkRole 3 is `nrhub`;
  - number-like text such as `08034` is quoted;
  - a loopback, VTI or interface zone that is missing from its segment's map is taken from the other segments' maps when they agree;
  - sitePriority and peer metrics get a ledger line;
  - the route ECOS makes for an auto-distribute VTI is not written as a static route.

Full entries: [CHANGELOG.md](../../CHANGELOG.md).

## Checked
- Offline unit and golden tests: 701 OK. CI ran on Linux and macOS, Python 3.9 and 3.13, plus the browser smoke and accessibility test.
- Release gate, run against rc.2 plus the unseen-field tiers:
  - 104 captures (99 stored, 5 from the lab), 3 targets (9.6.4 offline, 9.7.1, 10.0) and both commits: 624 translations, each followed by check.py.
  - On the 99 stored captures, the YAML is byte-identical on every target.
  - 0 crashes, 0 silent drops and 0 secret leaks.
  - `/validate` on the virtual lab's 9.7.1 Orchestrator: the only failures are the known ones (a branch NAT rule on a VLAN subinterface, which the toolkit refuses deliberately; a capture taken while the appliance was offline; the lab's deliberate rejects), plus two lab VRRP builds that the 8-character stand-in now fixes.
- Not checked:
  - Windows/WSL and browsers other than Chromium.
  - The 10 paths written for 9.6.x targets, which 9.7.1 `/validate` accepts but no 9.6.x Orchestrator has validated.
