# 1.4.0-rc.1: local web GUI (pre-release)

A pre-release from the `gui` branch. `main` and its Latest release (1.3.2) are unchanged.

## What's new
- **Local web GUI**: `edgeconnect-preconfig gui` (or `python3 -m toolkit.gui`) `[--port P] [--no-browser]`. See `docs/GUI.md`.
  - Build a template from an appliance and choose what changes per site, alone or compared with up to 4 other sites, with each site's own value shown beside the base's.
  - Make, validate and upload the preconfig files, and upload existing YAML files.
  - Inventory: see the appliances and the preconfigs on an Orchestrator.
  - Run log as tables.
- **Same commands as the terminal**: the GUI runs the toolkit's commands in-process, and the command line's own output is unchanged.
- **Uploads**:
  - They are off until `<nick>_gui_preconfig_uploads=on` is set in `.env`.
  - A CSV upload needs the Orchestrator's nickname typed. A YAML upload is one button.
  - Nothing ever applies a preconfig.
- **CLI additions the GUI uses** (all listed in CHANGELOG.md under 1.4.0-rc.1):
  - run context, recorder and run log;
  - the upload approval hook;
  - `preconfigs`;
  - `variables --fix/--dry-run`;
  - `compare --dry-run/--set/--fix/--captures`;
  - the 1.3.4 compare fixes;
  - distinct route labels;
  - Bearer redaction in the run log.
- **Fixes**:
  - Multicast that is switched on without an RP is no longer written, which /validate rejected (since 1.3.0). It is listed under Gaps, and check.py flags it offline.
  - A capture taken while the appliance was unreachable now says so.
  - A GUI dialog no longer stays open after you leave its page.
  - Run log: an upload where every row conflicts is logged BLOCKED, and an approval refused in the GUI gets its own REFUSED line.
  - A `setup.sh` re-run keeps each clone on its branch.

## Checked
- Offline unit tests on Linux and macOS, Python 3.9 and 3.13.
- A browser smoke test (from an appliance to written YAML) and an axe accessibility check on every screen in both themes, in CI.
- 83 stored appliance captures: offline output is identical to 1.3.2 apart from the version line and the fixes above, and there are no crashes. Orchestrator /validate on the virtual lab passed 81 of 83; the other two are an old capture taken while the appliance was offline and the deliberate NAT-on-VLAN-subinterface guard.
- By hand on Ubuntu 24.04 over SSH (docs/gui/ubuntu-ssh-check.md): every check passed.
- A live upload through the GUI on the virtual lab (CSV with the typed nickname, YAML with one button; both read back as uploaded, `autoApply` off, then deleted).
- Not checked: Windows/WSL and browsers other than Chromium.
