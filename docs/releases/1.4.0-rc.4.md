# 1.4.0-rc.4: every captured field accounted for (pre-release)

A pre-release from the `gui` branch, after [1.4.0-rc.3](1.4.0-rc.3.md). rc.3 was tagged in the changelog but not published. `main` and its Latest release (1.3.2) are unchanged.

## What changed since 1.4.0-rc.3
- **A new check proves every captured field is accounted for** (`tests/harnesses/source_coverage.py`). It runs the converter with every read wrapped and lists each field that was neither written, nor named in the ledger, nor on `tests/harnesses/source_ignore.yaml` with a reason. Over 109 captures (99 field captures and 10 full-coverage lab captures) and 3 targets, it went from 890 untraced fields to 0 in five rounds. This is the other half of check 11, which proves every "mapped" ledger line has its YAML value.
- **Settings that were dropped are now written:**
  - an IP SLA http/https monitor's "force DNS through the probe path";
  - a non-Default segment route's advertise flags, from the segment's own configured table (capture reads `subnets3/configured/vrfs/<id>`);
  - a combo port in SFP mode (`comboPortMode: 3`, lan2/wan2 of EC-10106/10108), which `/validate` on 9.7.1 accepts. No combo-port model has applied it yet.
- **OSPF set by a template group is left out**, field by field, as routes, bgp and vrrp already were. Before, the `bfd` and `ospf` templates were never matched to their sections. BFD timers a template sets stay written with a ledger line, because `/validate` refuses a BFD entry without them.
- **A passthrough tunnel in a non-Default segment** is no longer written into Default. It is held out with a gap line until a validated build has a tunnel segment.
- **Settings the format has no field for get a ledger line** instead of being dropped with no line:
  - BGP neighbor-change logging;
  - remote DHCP pool failover;
  - a route's VXLAN next-hop settings;
  - an inbound bandwidth limit that is switched off;
  - a tunnel's FEC, tag and unshaped settings.
- **The VRRP key placeholder is always `<SECRET:vrrp.auth>`**, so a re-capture shows no change.
- **Two ECOS 9.6.2.1 apply traps are documented** in `references/known-constraints.yaml`, and the first is now ledgered:
  - a fixed speed with duplex auto applies with no error but changes nothing;
  - the multicast section is refused even at its default.
- **GUI:** a build shows every capture request. The last lines were lost when the capture folder was renamed.

Full entries: [CHANGELOG.md](../../CHANGELOG.md).

## Checked
- Offline unit and golden tests, and CI on Linux and macOS with Python 3.9 and 3.13, plus the browser smoke and accessibility test.
- Source coverage: 0 untraced fields over 109 captures and 3 targets. One capture fails as before: it was taken while the appliance was offline.
- Release gate (rc.3 against rc.4, 109 captures, 3 targets): 65 YAML leaves changed, all intended (the combo port on two EC-10106 builds, the VRRP placeholder, http-monitor force DNS). check.py verdicts and exit codes are identical. 0 crashes beyond the known offline capture, 0 silent drops, 0 secret leaks. `/validate` on 9.7.1 accepted every build the offline pre-check let through; the others were the lab's deliberate rejects.
- Not checked:
  - Windows/WSL and browsers other than Chromium.
  - The 10 paths written for 9.6.x targets, which 9.7.1 `/validate` accepts but no 9.6.x Orchestrator has validated.
  - A tunnel segment: no capture has an unmarked tunnel outside Default.
  - The segment-route advertise flags: no stored capture has the new read. They were proven once live on the lab (a re-capture gave F/F/T as configured).
