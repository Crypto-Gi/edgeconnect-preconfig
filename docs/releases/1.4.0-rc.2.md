# 1.4.0-rc.2: converter fixes for Orchestrator 10.0 (pre-release)

A pre-release from the `gui` branch, after [1.4.0-rc.1](1.4.0-rc.1.md). `main` and its Latest release (1.3.2) are unchanged. The local web GUI is as in rc.1; this release changes what the converter writes and how it refuses a bad `.env`.

## What changed since 1.4.0-rc.1
- **A value of the wrong type is no longer written.** Every value is checked against the target release's default template:
  - a yes/no field that holds something other than true or false;
  - an object or list in a number or text field;
  - a null item in a list.

  Such a value is left out and listed under Gaps in `summary.md`. A list whose every item is bad is not written at all, never as an empty list. BGP and OSPF `bfdEnabled` are checked as yes/no, and a VRRP `tracker` reported as `""` is written as false.
- **A switched-off multicast segment is left out.** The factory default every 9.7 appliance reports (disabled, with no RP, PIM, IGMP or filter) is ledgered `default-omitted` instead of written.
- **Secure web services on Orchestrator 10.0.** Orchestrator 10.0 reports `flowProcess` as null, which its `/validate` refuses. A null is now written as the 10.0 template default `true`, with a ledger line. A section with only defaults is left out, as on 9.x.
- **A base URL copied from the browser** (for example `.../webui/login`) is refused with one line instead of a JSON traceback. A path is allowed only when it ends in `/gms/rest`.

Full entries: [CHANGELOG.md](../../CHANGELOG.md).

## Checked
- Offline unit and golden tests on Linux and macOS, Python 3.9 and 3.13, and the browser smoke and accessibility test, in CI.
- An Orchestrator 10.0 run: every 10.0 build passed `/validate` on a 10.0 Orchestrator, and the 9.7 and 10.0 target YAML were identical.
- A 10.0-target fuzz run (720 broken API answers).
- 83 stored appliance captures against rc.1: 82 are byte-identical apart from the version line, with no crashes. The other one differs only by the two intended omissions above (a switched-off multicast segment, and a defaults-only secure web services section with a null `flowProcess`). Orchestrator `/validate` on the virtual lab: 81 of 83, as in rc.1. The other two are an old capture taken while the appliance was offline and the deliberate NAT-on-VLAN-subinterface guard.
- Not checked: Windows/WSL and browsers other than Chromium.
